## 2. Findings per gap
### Gap 1-2 Thermal and sustained fps
- No public Dimensity 8400 / G720 MC7 frequency-voltage or watt curve found. Spec snippets only: GPU up to 1.3 GHz, 3DMark WLE stability 61.5%. Search snippets say MediaTek's OPP table sits in a closed vendor .ko. [to verify, snippets] KNOWN (confirms 09-30/10-03 negatives). Why it matters: do not wait for data; infer the GPU clock from our own counters (active Mcyc/s at saturation: 1.03-1.08 G in b208, 0.59 G in the "capped" b185).
- Physics argument [inference]: dynamic energy per frame ~ V^2 x cycles, so what lowers heat is cycles per frame (we measure 19-23 Mcyc) and the lowest OPP that still meets the deadline. A fixed 60 cap with spare GPU time lets the governor pick a lower OPP; an uncapped run bursts. Only testable once GPU work < ~15 ms.
- ADPF thermal headroom, official doc: poll no faster than every 10 s, one thread, NaN if faster or unsupported; >0.85 light throttling likely, >0.95 moderate, >=1.0 severe; getThermalHeadroomThresholds exists from Android 15; docs recommend cutting frame rate, resolution, fidelity or moving threads to small cores. https://developer.android.com/games/optimize/adpf/thermal (read 2026-10-04). [verified] KNOWN (API) / NEW (threshold mapping).
- Android docs: the system may override setFrameRate on thermal/battery/load; request only a rate you really reach. https://developer.android.com/games/optimize/display-refresh-rate-change (2026-10-04). [verified] NEW. The same page was summarised as "Android 15 games default to 60 Hz"; that claim comes from a secondary summary and a news site [to verify].
- Reddit D8400 anecdotes: a Poco X7 Pro user turns PostFX and AO off in Saints Row (Winlator, 720p) because they "eat huge numbers of FPS"; another D8400 user runs DMC4 with a cooler. https://www.reddit.com/r/EmulationMediatekMali/comments/1wvzerh/ , /1wwyi4f/ (10-02, 10-03). [to verify, anecdotes] NEW.

### Gap 3 Frame pacing
- Device extension list (the gpuinfo report our notes already use, https://vulkan.gpuinfo.org/displayreport.php?id=47424, Xiaomi 25069PTEBG, Mali-G720 MC7, driver 49.1.0, read 2026-10-04): PRESENT: VK_GOOGLE_display_timing, VK_EXT_swapchain_maintenance1, VK_KHR_incremental_present, VK_EXT_pipeline_creation_cache_control, VK_EXT_pipeline_creation_feedback, VK_KHR_push_descriptor, VK_KHR_draw_indirect_count. ABSENT: VK_KHR_present_wait/present_id, VK_EXT_graphics_pipeline_library, VK_EXT_descriptor_buffer, VK_EXT_shader_object, VK_EXT_external_memory_host, VK_EXT_multi_draw, VK_EXT_host_image_copy. [verified, device report] Partly KNOWN (push_descriptor, no descriptor_buffer, no external_memory_host); NEW: no GPL, no present_wait, no shader_object, no multi_draw.
- VK_EXT_present_timing needs Android 17 (official). https://developer.android.com/games/develop/vulkan/frame-pacing-extensions [verified] KNOWN. The page gives no FIFO/MAILBOX or image-count advice.
- mw2-recompiled presents FIFO, 4 present images (3 frames ahead), one present per vblank, and slaves the guest vblank to the display period using VK_KHR_present_wait (period from the exact mode rate, 0.5% longer while >1.5 frames queue). https://github.com/PaulCombal/mw2-recompiled/blob/master/docs/rendering.md (read 2026-10-04). [verified] NEW. r49p1 has no present_wait, so the equivalent would be VK_GOOGLE_display_timing (vkGetPastPresentationTimingGOOGLE).
- Local code (read only): vulkan_presenter.cc ~1480-1499 selects IMMEDIATE, else MAILBOX, else FIFO_RELAXED, else FIFO; presenter.cc and EmulatorHostActivity.kt already call setFrameRate for frame generation. Conditions around those lines were not read. [local code, partial] Why it matters [inference]: a non-FIFO mode at 55-58 fps on a 120 Hz panel gives uneven frame spacing even when the median looks fine.

### Gap 4 Camera-turn hitches
- GPL is not exposed on r49p1 (above), so the "link pipeline libraries at draw" route is closed. [verified] NEW.
- mw2-recompiled uses GPL where present: hooks the title's T_D3D_InitPixelShader/InitVertexShader to compile at shader creation, workers pause during play (30 consecutive world frames), records every built pipeline (microcode + state) to MW2_SHADER_CACHE and rebuilds all at startup, persists VkPipelineCache. A Windows/AMD driver crash in its first shader compile is worked around with MW2_NO_PIPELINE_LIBRARIES=1 (issue #2, 10-03). Docs rendering.md "Pipelines" + https://github.com/PaulCombal/mw2-recompiled/issues/2 [verified] NEW. The no-GPL equivalent for us is the recorded-state precreate at load (our .xpso, precreate currently false) plus skip_draws=false; this is already in the sheet (10-03 15:30), the design reference is new.
- VK_EXT_pipeline_creation_cache_control is present, so a "fail if compile required" probe (the Cemu policy in the sheet) is implementable. [verified extension; use is inference]
- Caution [inference from the sheet]: only a handful of pipelines are created during gameplay, while textures churn at 70-100 creations/s at the 256 MB cap. Camera-turn hitches are more likely texture creation/first loads than pipelines. [not covered externally]

### Gap 7 Cheap "RT look"
- XeGTAO: MIT, archived 2024-04-22. HLSL SM6.3 / DX12 only, no GLSL or mobile port. Inputs: depth (16-bit float) and optional normals (built-in depth-to-normal). Three compute passes (depth prefilter, main, 5x5 depth-aware denoise). Cost: High 1080p 0.56 ms RTX 2060, 2.39 ms i7-1195G7 iGPU; Medium about 2/3 of High, Low about 2/3 of Medium; bent normals +25%; fp16 +5-20%. https://github.com/GameTechDev/XeGTAO README [verified] NEW.
- CACAO (MIT, FidelityFX SDK 1.1.4, local copy third_party/fidelityfx-sdk has GLSL callbacks ffx_cacao_callbacks_glsl.h): depth required, normals optional (generated from depth), downsampled mode (quarter-res deinterleaved), LOWEST..HIGH = plain SSAO, HIGHEST adds importance map + adaptive pass; chain prepare, SSAO, edge-aware blur (4 passes, 2 at lowest), apply, optional bilateral upsample. No ms table, no mobile claims. https://gpuopen.com/manuals/fidelityfx_sdk/techniques/combined-adaptive-compute-ambient-occlusion/ [verified] NEW. CAS: MIT repo, GLSL callbacks in the same SDK, needs linear colour, no cost documented.
- Other licenses (GitHub API 2026-10-04): ASSAO MIT (archived), SSRT3 MIT (Unity, PC), Filament Apache-2.0 (uses SAO because it was the best mobile compromise; GTAO only for multi-bounce, discussion #7797). NOT usable/unclear: reshade-shaders and qUINT/MXAO (no license), Snapdragon GSR (NOASSERTION), Arm ASR repo (API shows none; the earlier note says MIT, re-check LICENSE). [verified API; ASR to verify]
- Mali cost: no public measurement for GTAO/CACAO/SSAO on any Mali found. Scaling the iGPU number by pixels (1024x600 = 0.30 x 1080p) gives about 0.7 ms High and about 0.3 ms Low [inference, order of magnitude only], i.e. +2-4% of a 15-20 ms GPU frame, plus compute-queue serialisation we already see on Mali. Saints Row report above says game AO is expensive on this SoC [to verify].
- Depth source [inference from sheet RTFLOW/q205]: MW2 already resolves a 1024x600 scene depth (k_24_8_FLOAT) and a 1024x600 colour each frame, and q205 writes that depth straight into a texture, so an AO pass could read both without reconstruction. The depth-dual texture is not AFBC (our b217). Single known title, so no ReShade-style heuristic is needed.
- Sharpening/SSGI: no permissive, cheap SSGI found for mobile [not covered]. ReShade depth/HUD detection and emulator post-FX costs [not covered].

## 4. Top actionable proposals
Evidence is thin; these are ranked by expected effect on locked-60 and sustained fps.
1. Presenter audit and fixed-cadence FIFO. Confirm which mode the presenter really uses on the 120 Hz panel (IMMEDIATE/MAILBOX preferred in the code excerpts read). Test FIFO, 3-4 images, setFrameRate(60, FIXED_SOURCE), pace with VK_GOOGLE_display_timing (present_wait absent), judge by GuestFrameIntervals p90 and vkGetPastPresentationTimingGOOGLE. Cost low. Gain: even spacing; it does not raise the 55-58 median.
2. Thermal-aware cadence instead of a hidden halving. Log getThermalHeadroom from one background thread every 10 s (check it is not NaN on HyperOS 3) as a harness column; if valid, step an even cap (for example 60 to 45 or 40) at headroom >0.85 rather than letting the Mali cap swing fps 25-46. It changes cadence only, no visual cuts. Cost low-medium. Then test fixed 60 vs uncapped at equal start temperature with counter-derived GPU clock.
3. Pipeline/texture hitch fix for camera turns: precreate recorded pipelines at load (mw2-recompiled design, no GPL on r49p1), keep skip_draws=false, and log texture creations per second during camera turns to separate pipeline from texture-churn causes. Cost medium; partly in the sheet already.
4. Visual (optional, default off): CACAO (MIT, GLSL in the local SDK) in downsampled/lowest mode, or XeGTAO ported to GLSL at Low, run on the existing 1024x600 depth+colour resolves; estimate 0.3-0.7 ms [inference], enable only when GPU has headroom and thermal headroom <0.85. Measure with timestamp queries before any claim.

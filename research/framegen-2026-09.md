# Frame generation for XenDroid / MW2 on Mali-G720 - research 2026-09-29
Legend: [verified] = official doc/code or 2+ independent sources; [to verify] = single/weak source or snippet only. No Mali-G720 benchmark of any MV-free FG exists publicly (checked); every cost number below is from other GPUs.

## 0. Reality check (read first)
- "Zero visible artifacts" from 20-25 fps native, without game MVs, is not achievable by anyone. AMD: FSR3 FG best from >=60 fps, avoid <30 [verified, https://gpuopen.com/fidelityfx-super-resolution-3/]; Intel XeSS-FG min 40 [to verify]; Lossless Scaling: min 30, ideal 60, artifacts near-certain <30 [to verify, SEO guides]; Digital Foundry: 40-60 base felt responsive, 30-40 poor [to verify, snippet]. Target: native >=30-40 (1x res, no MSAA) -> FG 2x -> 60-80.
- Interpolation adds ~1 base frame latency (35-45 ms at 22-28 fps). Extrapolation (Adreno QCOM_frame_extrapolation takes only 2 previous textures [verified, https://registry.khronos.org/OpenGL/extensions/QCOM/QCOM_frame_extrapolation.txt]) has no added lag but a 40-50 ms prediction distance smears disocclusions. Use interpolation.
- FG costs GPU: Mob-FGSR = 11-13 ms for FG alone on Snapdragon 8 Gen 3, WITH MV+depth [verified, https://mob-fgsr.github.io/, SIGGRAPH 2024]. On a GPU-bound game this lowers the base fps (25 -> ~20) unless budgeted.

## 1. Options
A. LSFG 3.x (Lossless Scaling) - lsfg-vk / Android ports
- Quality: best-regarded MV-free FG (smoother than AFMF2, more ghosting on HUD/crosshair/particles) [to verify, https://en.gamegpu.com/news/zhelezo/nvidia-smooth-motion-unichtozhila-lossless-scaling]. LSFG 3.1: perf mode "up to 2x less GPU", less ghosting/border/UI artifacts [verified, https://losslessscaling.com/lsfg-3-1/]. Flow scale 0.25-1.0 = motion-estimation resolution.
- Mali cost: unknown. lsfg-vk 2.0 (Sep 2026): bindless pipeline, Vulkan 1.2, FP16 path 2-3x on 2:1-FP16 GPUs, ~30% memory [verified, https://www.gamingonlinux.com/2026/09/lossless-scalings-frame-generation-for-linux-lsfg-vk-2-0-is-out-now/]. GameNative presets flow 40/50/70% cut compute 40-60% [verified, GameNative PR #1911 text].
- Needs: color only (no MV, no depth). Built-in UI detection.
- License: shaders are in the proprietary Lossless.dll -> a licensed copy of Lossless Scaling on Steam is needed to supply the DLL, nothing redistributable [verified: LSFG-Android README, Eden PR #4263, GameNative PR #1911, GamingOnLinux]. lsfg-vk 2.0 is CC BY-NC-ND (no derivatives) [to verify, https://lsfg-vk.dev/, one source].
- Android/Mali status: LSFG-Android (MediaProjection overlay, +50-80 ms latency, Adreno 7xx+ only, Mali stuck in mirror mode: capture feedback loop on G77) [verified, https://github.com/FrankBarretta/LSFG-Android, issue #12; created 2026-04-27, last push 2026-05-09]. In-process route works: Eden PR #4263 "Initial implementation of LSFG-VK" merged 2026-08-17, +4735 lines/69 files, C++ Vulkan, AHardwareBuffer-native path because Adreno/Mali refuse vkGetMemoryFdKHR on AHB memory [verified, https://git.eden-emu.dev/eden-emu/eden/pulls/4263]. GameNative PR #1911 (DXBC->SPIR-V of the proprietary DLL at runtime via DXVK dxbc, FP16 variants, shader cache, Turnip/Adreno/Panfrost tested) was CLOSED unmerged 2026-09-09 [verified, https://github.com/utkarshdalal/GameNative/pull/1911]. Mali reports are bad/unclear: Eden issue #670, Mali-G57 crash with LSFG on [to verify, https://github.com/eden-emulator/Issue-Reports/issues/670]. No confirmed run on Mali-G720.
- Integrability: Eden and GameNative are GPL-3 (XenDroid repo has no license set [verified, GitHub API]) -> fine as private reference, copying code needs care [to verify].

B. FSR 3/3.1 Frame Generation + FidelityFX Optical Flow (MIT)
- Needs: render-res MVs + depth (+reactive masks; optional HUD-less color) [verified, GPUOpen]. No documented "optical-flow only" mode. But the interpolation pipeline is public and MV-tolerant by design: 9 passes (dilated depth, game-MV field, MV inpainting pyramid, optical-flow field, dual disocclusion masks, interpolation preferring optical flow when color similarity is better, inpainting pyramid, inpainting) [verified, https://gpuopen.com/manuals/fidelityfx_sdk/techniques/frame-interpolation/].
- FFX Optical Flow standalone: color-only input, 8x8 blocks, R16G16_SINT MVs + scene-change flag, 3 passes x 7 iterations (24x24 luma search, 3x3 median, 2x upscale), needs wave ops + MSAD4, documented for DX12 [verified, https://gpuopen.com/manuals/fidelityfx_sdk/techniques/optical-flow/]. This is the engine of AFMF (driver FG without MVs; lower quality than FSR3 and "fallback" disables it in intense scenes [verified, PC Gamer/Tom's Hardware AFMF pages]).
- Mali cost: no data; shaders assume wave32/64, Valhall subgroup is 16 [to verify]. Effort high, license MIT (best). FSR4/Redstone ML FG = RDNA4 only [verified, https://www.tweaktown.com/news/109283/].

## 4. Anti-jelly recipe (design; sources = FSR3/FFX docs unless noted)
- Jelly = per-block vectors that flicker frame to frame and cross object edges. Fix: dense/sub-block flow at 1/4 res from a luma pyramid (3-4 levels, coarse-to-fine), seed the search with the previous pair's flow (temporal stability), 3x3 median, then edge-aware (color/depth-guided) upsample.
- Bidirectional flow + forward/backward consistency -> disocclusion masks per direction; in masked pixels take the valid neighbor frame only and fill holes from a mip-chain inpainting pyramid, never blend (blend = ghost) [verified FSR3 steps 6-9].
- Depth (if the EDRAM resolve exposes it): dilate depth so foreground wins in splatting, snap flow to depth edges [verified FSR3 steps 2-3]. DAIN-style depth-aware warp is the academic precedent [to verify].
- Fixed MW2 HUD: static mask, composite the HUD from frame N on top of the warped image; scene-cut flag (FFX OF) -> repeat frame; low confidence -> repeat/blend-free fallback (AFMF does this).
- Bound warp magnitude; blend t=0.5 only where both warps agree.

## 5. RANKED RECOMMENDATION
1. LSFG pipeline inside the presenter, with the proprietary Lossless.dll (Eden #4263 approach; read its code at git.eden-emu.dev). Best proven MV-free quality, closest precedent (C++ Vulkan emulator on Android). Plan: (a) 1-2 day gate, no integration: run the pipeline in a tiny Vulkan test app on the Poco with 720p frame pairs from MW2; measure GPU ms at flow 0.5 + perf mode; go if <=6-8 ms per generated frame and no jelly on strafe/turn/sprint. Quality test: record MW2 at a low setting (~45-50 fps), drop every 2nd frame, interpolate, compare with PSNR/SSIM + eyes. (b) hook after the guest swap in the Xenia Vulkan presenter (own the swap => exact frame times): hold N-1/N, generate mid, present N-1, mid, N paced to the display; fixed 30 fps base limiter for even cadence; MW2 HUD rect mask; scene-change/loading -> off. (c) needs AHardwareBuffer-safe memory (Mali refuses vkGetMemoryFdKHR on AHB memory).
2. Fallback if the gate fails on Mali or the DLL dependency is unacceptable: own MIT pipeline copying FFX Optical Flow + FSR3 disocclusion/inpainting pass structure as GLSL compute (section 4), feeding zero game MVs. Slower to build, no legal ties, quality unproven; expect AFMF-class results.
AVOID: LSFG-Android/MediaProjection overlays (+50-80 ms, Mali broken); root/zygisk modules; RIFE/NN (~100 ms/frame); MFRC/Game Space (SDK-gated, needs MV+depth, likely off on Poco X7 Pro); FSR4/XeSS/Smooth Motion/NFRU/Neural Fusion/Mob-FGSR (need MVs or vendor HW); Snap888/lsfg-vk as a dependency; plain block matching again (that is the jelly); interpolating from 20-25 base without first raising native fps.
